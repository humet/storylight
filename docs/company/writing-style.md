# Storylight Writing Style

## Product voice

Storylight is:

- warm
- calm
- thoughtful
- quietly playful
- reassuring
- direct

Storylight is not:

- corporate
- breathless
- sarcastic
- patronising
- overly cute
- technically self-conscious

## Interface copy

Prefer:

- New adventure
- Continue tonight
- Read again
- Choose who appears
- Painting this page
- Try another version

Avoid:

- Generate content
- Execute prompt
- AI response
- Processing tokens
- Launch narrative workflow

## Loading copy

Loading text should describe meaningful progress without pretending the result is already complete.

Good:

- Planning the adventure
- Writing tonight’s chapter
- Checking the story
- Painting the first page

Avoid fake magic that obscures an error or creates false certainty.

## Errors

Errors should be calm, honest, and actionable.

Good:

> This chapter did not come together properly. Your series is safe, and you can try again.

Avoid blaming the parent or showing provider messages.

## Parent-facing explanations

Explain decisions plainly:

> Because later chapters already depend on this event, Storylight can rewrite the wording and dialogue but cannot change how the chapter ends.

## Story prose

Story prose should:

- read naturally aloud
- use specific sensory details
- distinguish character voices
- avoid repetitive moralising
- avoid generic fantasy filler
- close with warmth
- respect the reading age without becoming flat

## Golden rule

If the copy sounds like software when it does not need to, rewrite it.
