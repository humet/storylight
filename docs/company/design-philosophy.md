# Storylight Design Philosophy

## Story first

The interface supports the book and then disappears.

## Calm

Use space, restrained motion, soft surfaces, and predictable hierarchy. Avoid dashboards filled with counters, badges, and status widgets.

## Warmth

The visual system should feel human and tactile without pretending to be a physical book. Subtle texture is acceptable; noisy skeuomorphism is not.

## Mobile clarity

The core composition must work at phone size. Important faces, controls, and reading text should remain clear without zoom.

## Motion with meaning

Use motion to communicate:

- opening a book
- revealing a chapter
- moving between story sections
- confirming a saved action

Avoid ornamental bouncing, spinning, and constant ambient animation.

## Illustration above interface

Story images can dominate the page. Controls should not compete with them.

## Night comfort

Dark mode should feel like warm lamplight, not a high-contrast developer theme.

## Consistency

One series must feel like one book. Typography, spacing, image treatment, and character rendering should not change unpredictably.

## Design test

Ask:

> Would this still feel appropriate if it were printed in a high-quality children’s book?

If not, simplify.
