# User Journeys

## 1. First-time parent setup

1. Parent creates or signs into a private family account.
2. Storylight explains that child photos are not required.
3. Parent creates the first child-character profile from structured appearance details.
4. Storylight generates several illustrated candidates.
5. Parent approves one candidate.
6. Storylight creates additional identity views from that approved candidate.
7. Parent repeats for the second child.
8. The family library opens with a clear “Create tonight’s story” action.

Success means the parent understands the character is fictional, private, editable, and reusable.

## 2. Create a one-off story

1. Parent or child enters an idea.
2. Parent selects which child characters appear.
3. Parent chooses “Tonight’s story.”
4. Storylight applies saved defaults for age, length, tone, and suspense.
5. The Lantern Engine plans and writes the story.
6. The story passes review.
7. The first approved illustration appears.
8. The parent begins reading while remaining illustrations complete.

The complete story resolves in one session and closes calmly.

## 3. Start a series

1. Parent enters an idea.
2. Parent chooses “A story to continue.”
3. Parent selects a chapter count or accepts the default.
4. Storylight creates a hidden series bible.
5. Chapter 1 is generated from the first blueprint.
6. The series appears in the library with cover, premise, and progress.
7. Later chapters are not generated until requested unless pre-generation is enabled.

The child sees no spoilers.

## 4. Continue tonight’s series

1. Home displays the current series prominently.
2. Parent taps “Continue tonight.”
3. Storylight loads the next planned chapter.
4. The app shows calm progress and allows the parent to leave.
5. The approved chapter becomes available.
6. The chapter ends with local emotional resolution and gentle anticipation.
7. Progress updates to the next chapter.

## 5. Regenerate a chapter

Before publication or before any later chapter exists:

1. Parent chooses “Try another version.”
2. Parent optionally gives a reason.
3. Storylight generates a new immutable revision.
4. Continuity is recalculated from the accepted version.

If later chapters already exist, Storylight offers a constrained rewrite that preserves facts relied upon later.

## 6. Regenerate an illustration

1. Parent opens image options.
2. Parent chooses a concrete reason, such as “doesn’t look like them” or “wrong detail.”
3. Storylight creates a targeted repair request.
4. The existing approved image remains visible until the replacement passes review.
5. The parent can keep the original if the repair is worse.

## 7. Return to a favourite story

1. Parent opens Library.
2. Stories can be filtered by one-off, series, completed, favourites, and characters.
3. A story opens at the beginning or the last reading position.
4. Historical content remains pinned to its original visual and model profiles.

## 8. Report a problem

The parent can report:

- too scary
- continuity error
- character behaved incorrectly
- illustration identity issue
- wrong object or clothing
- reading level mismatch

The report links to the exact chapter or image revision and model metadata.
